# 论文收录

## 仓库约定

仓库根目录是本 skill 所在 `.agents` 目录的上级，使用脚本默认定位或显式传入 `--repo`，不要依赖机器上的固定绝对路径。先查看 `README.md`、`example.md`、最近的笔记和 `papers/papers.md`，沿用当前风格。

- 以用户指定的**收录日期**分组；未指定时使用当前对话的日期，按 Asia/Shanghai 理解，勿以论文发表月份代替收录月份。
- 默认月份目录为 `YY_M`，不补月份前导零，例如 `26_7`、`26_11`；索引标题为 `# 26.11`。用户指定目录或日期时优先遵循其要求。
- 原文：`papers/YY_M/简称.pdf`；笔记：`papernotes/YY_M/简称.md`，两者同名。简称优先采用论文或方法名，如 `LibraryDesignBench`，不要使用 Windows 文件名非法字符。
- 笔记保留简介和作者信息的 HTML 注释、论文英文标题、来源与原文相对链接，以及“问题 / 方法 / 实验 / 附录 / Noun explanation && Extensive knowledge / 思考？”骨架。除一两句简介与已核实的元信息外，正文留空供用户阅读时填写。
- 在对应月份索引下记录论文标题与来源、笔记及原文 PDF 相对链接。保留已有条目、顺序、阅读状态与用户修改。

## 识别与核实

将每个独立链接、ID、标题视为候选论文，先核实再去重。不要假定相邻的标题一定属于前一个链接。arXiv / alphaXiv 的 `/abs/` 和 `/pdf/` 链接均可提取同一 arXiv ID；只有标题时，搜索作者或 arXiv 等一手来源，确定唯一论文。无法唯一识别时仅询问存在歧义的项目，继续处理其他已确认项目。

从论文摘要页核实题名、作者、版本和日期；机构、会议、代码地址应核对 PDF 首页或作者项目页。无法证实的字段留“待核实”，不要根据年份或第三方推断会议。简介由当前模型依据摘要简短概述，不直接复制整段摘要。多个入口指向同一论文时只收录一次。

## 执行

优先运行随附的 [scripts/add_paper.py](scripts/add_paper.py)，它负责元信息读取、PDF 下载校验、模板生成、月份索引写入与重复检测。以下命令均在仓库根目录执行：

```powershell
python -X utf8 .agents/skills/paper-intake/scripts/add_paper.py "https://www.alphaxiv.org/abs/2609.36730" --date 2026-11-03 --name LibraryDesignBench --summary "根据已核实摘要撰写的一两句中文简介。" --institutions "已核实的机构"
```

- 将示例参数换成当前论文与当前对话日期。`--date` 显式传递对话日期，避免执行主机日期不一致。
- `--name`、`--summary`、`--institutions`、`--venue`、`--code`、`--project` 均可选；省略 `--name` 时由标题生成文件名。`--month-dir` 可指定用户要求的月份目录；`--dry-run` 只报告路径和索引计划。
- 对非 arXiv 论文，先核实题名与可下载的原文地址，再传 `--title`、`--pdf-url`，按需补 `--authors`、`--published`；脚本不猜测标题搜索结果。
- 脚本依赖 `requests` 和 `pypdf`，缺失时才安装。下载优先使用 arXiv，失败时尝试另一个原文入口；验证 PDF 文件头与可解析页数，不把网页或下载失败响应保存为 PDF。
- 重复收录时复用已有笔记的名称与原目录，保留用户已写内容和有效 PDF，只补缺失文件或索引。文件名与其他论文冲突时更换简称，不能覆盖。
- 多篇可先独立核实元信息，逐篇运行写入脚本，避免同时修改索引。一篇失败时继续处理其余论文，不为失败下载创建成功记录。

默认只收录英文原文。用户另外要求翻译时再读取并使用仓库中的 `arxiv-translator/arxiv-translator/SKILL.md`；仅在中文 PDF 真正生成后，才给笔记和索引增加其相对链接。

## 核验与交付

检查新增 PDF 能打开、题名与目标论文相符，笔记和索引中的本地相对链接均存在。确认重复执行不会重复追加或覆盖已有笔记，运行 `git diff --check`。脚本使用临时 `.part` 文件，失败时清理自己创建的临时文件。

完成时给出 skill、笔记及索引路径，说明成功和未完成的项目；不要把待阅读模板标为“已读完”。
